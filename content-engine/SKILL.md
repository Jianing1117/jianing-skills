# 内容引擎

```
   别人的爆款 ──【学】──→ 拆解卡 ──→ 审阅 ──→ 方法论
                                              │
                                              │ 读
                                              ▼
   我的内容 ────【改】── 先诊断 ──→ 定位部位 ──→ 标题 / 开头 / 正文 / 切片
                                              │
                                              ▼
                                      发布 → 数据 ──【复盘】──┐
                                              ▲                │
                                              └────────────────┘
```

**方法论是轴。学写它，改读它，复盘校准它。** 引擎本身只是工序，判断依据一律去读文件——说不出依据的判断，是你在编，删掉。

## 写入纪律（红线）

1. **默认只在对话里输出，不落盘。**
2. **审阅门**：任何要落盘的内容，先在对话里出完整一版，逐条点头 / 否掉 / 改。**没有明确点头就不写。**
3. 获准后只写这三个地方：

   | 写什么 | 写去哪 |
   |---|---|
   | 提炼出的通用规律 ＋ 内嵌证据行 | 本 Skill `playbook.md` 对应小节 + 更新日志一行 |
   | 自家数据得出的结论 | vault `方法库/爆款心得与标题公式.md` + 该文件更新日志 |
   | 可迁移性判定结果（✅ / ⚠️ / ❌） | vault `方法库/适合我的爆款条件.md` 对应小节 |

   **拆解卡不落盘。** 它是给用户审阅用的中间产物，看完即弃——要留下的东西已经压缩进 playbook 条目的证据行里。**vault 结构零改动，不新增任何文件或文件夹。**

4. **宪法层（`系统规则/`）永不由本引擎修改。** 只能提议，留到月度复盘由用户决定。
5. 写 vault 前先打 checkpoint：`git -C "<vault>" add -A && git -C "<vault>" commit -m "checkpoint: content-engine 沉淀前"`
6. **脱敏铁则**：进 `playbook.md` 的内容不得包含真实经营数字、客户信息、未公开的个人经历。绝对数字改成量级或比率区间。

# 一、【学】拆爆款

输入：视频链接 / 转写 / 截图 / 点点的分析 / 用户自己的批注。有几样用几样，缺的就问，不猜。

### 流程

1. 读主控（形/神怎么分、什么是一票否决）＋ 现有 `playbook.md`（避免重复沉淀已有规律）
2. 出**拆解卡**（格式见下）
3. 出**可迁移性判定**
4. **交给用户审阅** —— 逐条点头 / 否掉 / 改
5. 通过的部分：提炼成规律写进 `playbook.md`，并把这条爆款压成一行证据挂在下面。**卡片本身不落盘。**
6. 可迁移性判定的结果落进 vault `方法库/适合我的爆款条件.md`——✅ 和 ⚠️ 进正文，❌ 进反面清单。**这是唯一记录「什么适合我」的地方，不落就白判了。**

### 拆解卡格式

```markdown
# [一句话说清这条爆了什么]

链接：            平台：          时长：
数据：粉丝 X · 赞 X · 藏 X · 评 X        低粉高赞倍数：赞/粉 = X
拆解日期：        素材来源：（自看 / 点点 / 用户批注）

## 爆在哪
[一句话说清它最主要靠什么爆的。只说一个原因，不要列五条。]

| | 形（做法，可模仿） | 神（为什么成立，模仿不了） |
|---|---|---|
| [爆点所在的那一层] | | |
| [还有第二处值得拆就加一行；没有就只留一行] | | |

## 可迁移性判定

| 条目 | 判定 | 说明 |
|---|---|---|
| [某条做法] | ✅ 直接可用 | |
| [某条做法] | ⚠️ 需翻译 | 翻译成本账号版本：[具体怎么改] |
| [某条做法] | ❌ 不可迁移 | 原因：资格不匹配 / 撞一票否决 / 偏离主线 |

## 落点
适合哪个版面：       建议出口：（图文 / 短视频 / 切片 / X 碎片）
如果要用，第一条可以这么写：[一个具体选题]
```

**先抓爆点，不要填表。** 大部分爆款的爆点集中在一两处，其余地方是正常水平——把七个格子填满，多出来的全是废话。写法是：先用一句话说清"它爆在哪"，然后只拆那一两处。

下面这张单子只用来**对照检查有没有漏掉的角度**，不是必填项：

> 选题 · 标题/封面文案 · 开头 3 秒 · 结构与节奏 · 信息密度 · 收尾与 CTA · 人格与语气

**这张单子也不封闭。** 爆点如果在选题时机、评论区运营、系列联动——当场写，不要硬塞进现有格子。同一个新角度出现 ≥2 次，就把它加进单子，并在 `playbook.md` 开对应小节。**方法论的分类本身也是学出来的。**

### 三条判定纪律

**可迁移性判定回答的是：别人的做法，我能不能照搬？** 拆完"它为什么爆"还不够——爆是它的事，能不能用是你的事。

| 档 | 意思 | 判据 |
|---|---|---|
| ✅ **直接可用** | 跟用户没冲突，照做就行 | 不撞红线、不需要特殊资格 |
| ⚠️ **需翻译** | 机制对，但原话用户说不出口。**保留机制，换掉表达** | 必须当场写出用户的版本 |
| ❌ **不可迁移** | 机制依赖用户没有的东西，或撞红线 | 资格不匹配 / 撞一票否决 / 偏离主线 |

**⚠️ 是最有价值的一档**，因为它逼出用户自己的版本。判了 ⚠️ 却写不出用户的版本 = 没判完，退回重想，或降级成 ❌。

- **形可以抄，神要问资格。** 主控 §2：「语气是形，可模仿；立场和经历是神，模仿不了。查神不查形。」一条"神"如果需要用户没有的经历或身份才成立，判 ❌——抄了就是拧巴。
- **撞一票否决直接 ❌**，不管数据多好。八条在主控 §2「永不说、永不做」。
- **低粉高赞要单独看**：粉丝少还爆，说明爆点几乎全在内容本身，不靠账号权重。这类卡的参考价值最高，`playbook.md` 里单开一节收。

### 进 playbook 的方式

卡片不留，所以**规律必须当场进 playbook**，否则下次就想不起来了。进的时候带一行证据：

```
- [链接] · 粉X 赞X · 赞粉比 X 倍 · [一句话：它在这条规律上具体做了什么]
```

| 置信度 | 条件 | 诊断时能不能当依据 |
|---|---|---|
| **参考** | 1 条证据 | 收进来并标注，**只作参考，不作依据** |
| **已印证** | ≥2 条**独立**证据 | 可以当依据引用 |
| **自家验证** | 自己发内容验证过 | 优先使用 |

被数据推翻的条目**不删也不降级**——在条目下加一行 `❌ 已推翻（日期·原因）`，正文划掉。反面教材和正面规律一样值钱。

第二条爆款指向同一条规律时，**不新开条目**——找到已有条目追加一行证据，升级置信度。

与 playbook 已有条目**冲突** → 不覆盖，并列写出来，两条都标"待验证"，等数据裁决。

# 二、【改】诊断并优化

**诊断先行。** 用户说"改开头""优化标题"，都先走一遍诊断——很多时候问题不在他说的那个部位。

### 第一步：诊断（永远先跑，不跳过）

按顺序，前面不过就别往后做：

**1. 主控四问**（读主控 §9，用用户自己的四问，不是通用四问）

四问不过是**选题层面的问题，改文案救不了**。直接告诉用户："这条的问题不在文案，在第 2 问没过。要么换角度重写，要么换选题。"

**2. 一票否决扫描**

逐条扫主控 §2「永不说、永不做」＋ 平台合规红线（诱导互动等，见 `craft.md`）。命中即必改，不商量。

**3. 全片四维**（不只看前 3 秒）

| 维度 | 看什么 | 判定 |
|---|---|---|
| **结构** | 属于哪种内容原型？骨架完整吗？缺哪一环？ | |
| **节奏** | 每 15–30 秒有没有继续看的理由？哪里有平段？ | |
| **信息密度** | 单位时间的新信息量。哪里注水、哪里过密到跟不上？ | |
| **收尾** | 有没有落回核心记忆点？带 slogan 了吗？**离场感是更安心还是更焦虑？** | |

**4. 完成度阶梯**（主控 §2）

60% = 只有语气 ｜ 80% = 语气 + 可截图的判断 ｜ 100% = 语气 + 判断 + 真实经历

判出档位，并说清**差什么才能上一档**。

### 诊断与手艺的分工（别让两边都写规则）

| | 负责 | 不负责 |
|---|---|---|
| **诊断（本文件）** | **判**——哪个部位有问题、多严重、定位到 `craft.md` 的哪一节 | 不给具体做法 |
| **`craft.md`** | **改**——每个部位的具体做法、模式、句式 | 不判好坏 |

同一个话题会在两边出现（"互动钩子"既是诊断维度也是手艺），**但方向相反**：诊断问「这里缺不缺钩子」，craft 答「钩子怎么写」。**规则只写一遍，写在 craft；诊断只引用，不复述。** 发现两边在写同一条规则，删掉诊断这边的。

### 第二步：定位部位，调用手艺

诊断出问题在哪，再去 `craft.md` 取对应方法：标题 / 开头 / 正文结构 / 互动钩子 / 切片。

同时读 `playbook.md`——有相关规律就用，并**注明依据哪一条**。

### 第三步：出修改建议

分两级，**每条都要给可直接替换的文本，不许只说"这里不够好"**：

```
🔴 必改：[问题] → [替换文本]     依据：[主控§X / playbook§X / 适合我的爆款条件§X]
🟡 建议：[问题] → [替换文本]     依据：...
```

只有两级。想不清楚该放哪一级的，就是 🟡。**凑不出理由的第三级"可选"，本质是噪音。**

逐段诊断格式：

```
### 第 N 段 ·「[原文首句…]」
诊断：
依据：
改法：[可直接替换的文本]
```

### 切片（长内容 → 短内容）

一支中长视频切出 3–5 条能独立成立的判断，每条写成 60 秒口播。

**判断 ≠ 步骤**——这是切片唯一的难点，也是最容易做砸的地方。筛选标准、60 秒骨架、输出要求见 `craft.md` §5。

# 三、【复盘】数据回流

### 周节拍

1. **查数据**：看 `复盘分析/数据/` 有没有新日期的导出文件（如 `笔记列表明细表YYYYMMDD.xlsx`）。没有 → 提醒一句，不催第二次。
2. **有就读**：结合历史数据做对比，**只做两件事**——
   - 记录本周表现
   - **挑异常值**：哪条突然起量、哪条低粉高赞、哪条明显扑了
3. **异常值反哺**：自己的低粉高赞内容，按【学】的流程拆自己一次，提炼出的规律进 `playbook.md`，证据行标注「自家验证」。

### 周不改方法论

**周数据样本太小，率是噪音。** 三五条内容的收藏率说明不了任何事——已有结论「收藏率 9% 是生态系统级内容的信号线」是一个月样本才敢下的。

| 节拍 | 做什么 |
|---|---|
| **周** | 记录 · 挑异常值 · 提议（不改） |
| **月** | 下结论 · 改 `playbook.md` / `爆款心得与标题公式.md` · GitHub 发版 |

例外：某条规律被数据**强烈打脸**（不是微弱波动），当周就提出来，标"待验证"并列写进去，不覆盖原条目。

### 月度复盘多跑一道

在已有的「台账 + 复盘初稿」之后，加一步**回看方法论**：

- 哪条被本月数据验证了？
- 哪条被推翻了？
- 哪张拆解卡够格从"单卡观察"升级成"已印证"？
- → 出提议清单 → 用户点头 → 才改

### GitHub 发版

**周节拍收口**：每周看一次 `playbook.md` 有没有变化，有就发版，没有就跳过。不攒着，也不硬凑。

两条来源，两种门槛：

| 规律来源 | 门槛 | 频率 |
|---|---|---|
| **拆解爆款** | 证据行写得出来就能进 | 随时，不等节拍 |
| **自家数据** | 需要足够样本才敢下结论 | 月度 |

拆解是主要增长来源，**不受样本量限制**——一条爆款就是一条真实证据，所以 playbook 每周有东西可发是正常的。只有从**自己数据**得出的结论要等月度，因为周维度三五条内容的率是噪音。

发版前：

1. 脱敏检查（真实数字、客户信息、未公开经历——一律不进）
2. 更新 `playbook.md` 顶部版本号与文末更新日志
3. commit message 写清这版学到了什么，让 git log 本身就是一部方法论进化史

## 点点（小红书智能体）协作

用户可以先用点点分析爆文，把结果带回来。引擎的职责是**评估，不是照收**：

- 点点更懂平台侧（用户偏好、流量分布、平台当下的口味）
- 引擎更懂用户侧（资格、判准、一致性）
- 冲突时**并列写出来**，标清哪条是点点说的、哪条是引擎判断，交给用户裁决

点点给的结论同样要过**可迁移性判定**才能进 playbook——平台上有效 ≠ 这个账号能用。
